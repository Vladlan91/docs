## Огляд

Редактор Workflow — це візуальний інструмент на основі вузлів для проєктування логіки розмов. Перетягуйте та з'єднуйте вузли для створення складних потоків розмов.

## Типи вузлів

### Вузол Start
Точка входу для кожного workflow. Кожен workflow має рівно один вузол Start.

### Вузол LLM
Надсилає повідомлення до налаштованої AI моделі та повертає відповідь.

**Налаштування:**
- Temperature (0.0 - 1.0)
- Max tokens
- Користувацьке перевизначення system prompt

### Вузол Condition
Розгалужує workflow на основі умов. Підтримує:
- Збіг за ключовими словами
- Аналіз тональності
- Користувацькі вирази

### Вузол Tool Call
Виконує зовнішню функцію або API виклик. Результати передаються назад у контекст розмови.

### Вузол Voice Call
Обробляє голосову взаємодію — розпізнавання та синтез мовлення.

### Вузол End
Завершує розмову з необов'язковим заключним повідомленням.

## З'єднання вузлів

Натисніть на вихідний порт вузла та перетягніть до вхідного порту іншого вузла, щоб створити з'єднання. Кожне з'єднання представляє можливий шлях розмови.

## Найкращі практики

<Tip>
  Завжди вибудовуйте явні шляхи між вузлами з чіткими умовами. Однак у деяких випадках AI може самостійно направити повідомлення до вузла, до якого немає прямого з'єднання — це називається **сінапс**. Сінапси виникають, коли AI визначає, що існуючі умови маршрутизації нечіткі або недостатні, і самостійно вирішує дістатися до вузла. Хоча це додає гнучкості, часті сінапси зазвичай вказують на те, що умови з'єднань потрібно зробити більш конкретними.
</Tip>

- Зберігайте workflow простими — складні потоки важче відлагоджувати
- Використовуйте вузли Condition для обробки граничних випадків
- Тестуйте кожен шлях окремо перед публікацією

## Генерація воркфлоу за допомогою Claude Code

Якщо ви хочете створити кастомний воркфлоу для вашого AI-агента на основі бізнес-вимог, ви можете використати **Claude Code** для генерації готового JSON-шаблону воркфлоу.

<Accordion title="Промпт для генерації воркфлоу">
```text
# Інструкція: Генерація JSON-шаблону воркфлоу Revol

## Контекст

Я використовую Revol — платформу для створення AI-агентів
продажів. Кожен агент має візуальний редактор воркфлоу з
нодами та зв'язками (edges), що визначають логіку розмови.

Мені потрібно згенерувати шаблон воркфлоу як JSON-об'єкт,
який я можу імпортувати у свого Revol-агента. JSON
відповідає строгій схемі системи шаблонів Revol.

## JSON-схема

Результат має бути єдиним JSON-об'єктом з такими ключами:

{
  "nodes_data": [...],
  "edges_data": [...],
  "tools_data": {...},
  "memory_fields_data": [...]   // опціонально
}

### nodes_data (масив об'єктів)

Кожен об'єкт ноди має такі поля:

| Поле | Тип | Обов'язкове | Опис |
|------|-----|-------------|------|
| index | integer | так | Унікальний індекс (від 0), використовується для посилань у edges |
| node_type | string | так | Один з: start, custom, system_stt, system_tts, system_product, system_media, system_company, system_formatter |
| name | string | так | Назва на canvas |
| position_x | integer | так | X-координата на canvas |
| position_y | integer | так | Y-координата на canvas |
| is_active | boolean | так | Чи активна нода |
| conversation_goal | string | ні | Системний промпт для ноди (тільки custom ноди) |
| config | object | ні | Конфігурація ноди (див. нижче) |
| llm_provider_override | string | ні | Перевизначити LLM провайдера: openai, anthropic, gemini, groq |
| llm_model_override | string | ні | Перевизначити модель |
| temperature_override | number | ні | Перевизначити temperature (0.0-2.0) |

Типи нод та їх призначення:
- start — точка входу, рівно одна на воркфлоу, без conversation_goal
- custom — LLM-нода з власним промптом, інструментами та базою знань
- system_product — пошук товарів, перевірка наявності, деталі
- system_media — отримання фото, відео, документів
- system_company — інформація про компанію та підтримка
- system_formatter — об'єднує результати паралельних нод у фінальну відповідь
- system_stt — розпізнавання мовлення (голосовий ввід), зазвичай неактивна
- system_tts — синтез мовлення (голосовий вивід), зазвичай неактивна

Конфіг для system_stt:
{
  "provider": "openai",
  "language": "uk",
  "greeting_text": "Привіт! Чим можу допомогти?",
  "greeting_audio_url": null,
  "farewell_text": "Дякую! До побачення!",
  "farewell_audio_url": null
}

Конфіг для system_tts:
{
  "provider": "openai",
  "voice": "nova",
  "model": "tts-1",
  "speed": 1.0
}

Конфіг для custom нод (опціонально):
{
  "save_to_memory": ["field_key1", "field_key2"],
  "max_tool_rounds": 3,
  "tool_timeout_seconds": 30
}

### edges_data (масив об'єктів)

Кожен об'єкт edge з'єднує дві ноди:

| Поле | Тип | Обов'язкове | Опис |
|------|-----|-------------|------|
| source_index | integer | так | Індекс ноди-джерела |
| target_index | integer | так | Індекс ноди-цілі |
| condition_type | string | так | Один з: always, keyword, intent, state, fallback |
| condition_value | object | ні | Параметри умови (null для always/fallback) |
| priority | integer | ні | Пріоритет оцінки (за замовчуванням: 90 для always) |

Типи умов та пріоритети:
- keyword (пріоритет: 100) — збіг слів у повідомленні
  condition_value: { "keywords": ["слово1", "слово2", ...] }
- state (пріоритет: 95) — перевірка значень полів пам'яті
  condition_value: { "conditions": [{"field": "name", "operator": "filled|empty|=|!=|contains|>|<", "value": ""}] }
- always (пріоритет: 90) — безумовний, дозволяє паралельне розгалуження
  condition_value: null
- intent (пріоритет: 50) — LLM класифікує намір повідомлення
  condition_value: { "intents": ["intent_name"] }
- fallback (пріоритет: 10) — спрацьовує тільки коли нічого інше не підійшло
  condition_value: null

### tools_data (об'єкт, ключі — індекси нод як рядки)

Зіставляє індекс ноди з масивом назв інструментів:

{
  "2": ["search_documents", "get_company_info"],
  "3": ["get_products", "get_product_details"]
}

Доступні вбудовані інструменти (9):
- get_products — пошук товарів за назвою/описом
- get_product_details — повна інформація про один товар
- check_availability — перевірка наявності товару
- search_by_parameters — фільтрація товарів за атрибутами
- get_company_info — назва, опис, контакти компанії
- search_documents — семантичний RAG-пошук у базі знань
- get_photos — отримання фото
- get_videos — отримання відео
- get_documents — отримання PDF/Word/Excel файлів

### memory_fields_data (опціональний масив)

Визначає структуровані поля для збору даних агентом:

[
  {"key": "client_name", "label": "Ім'я клієнта", "type": "text"},
  {"key": "client_phone", "label": "Телефон", "type": "phone"},
  {"key": "topic", "label": "Тема", "type": "select", "options": ["продажі", "підтримка"]}
]

Типи полів: text, phone, email, number, select (з масивом options).

## Паттерни воркфлоу

### Паттерн 1: Простий (один експерт)
Start → Custom Node → Formatter
Найкраще для: FAQ-боти, проста підтримка, одна тема.

### Паттерн 2: Паралельні експерти (always маршрутизація)
Start → Експерт A → Formatter
      → Експерт B → Formatter
      → Експерт C → Formatter
Найкраще для: агенти, яким потрібно шукати товари + документи + інфо про компанію одночасно.

### Паттерн 3: Розумний маршрутизатор (intent/keyword маршрутизація)
Start → (intent: sales) → Експерт з продажів → Formatter
      → (intent: support) → Експерт з підтримки → Formatter
      → (fallback) → Загальний експерт → Formatter
Найкраще для: мультитематичні агенти, де різні питання потребують різної експертизи.

### Паттерн 4: Збір лідів (state маршрутизація)
Start → (ім'я пусте) → Збір імені → Formatter
      → (ім'я заповнене, телефон пустий) → Збір телефону → Formatter
      → (все заповнене) → Фінальна відповідь → Formatter
Найкраще для: кваліфікація лідів, бронювання, заповнення форм.

### Паттерн 5: Голосовий агент
STT → Start → Експерт → Formatter → TTS
Те саме що будь-який паттерн вище, але з активними STT/TTS нодами.

## Рекомендації з розташування

- Start нода на позиції (0, 0)
- STT нода зліва: (-200, 0)
- Ноди-експерти справа: (200, -100), (200, 0), (200, 100)
- Formatter далі справа: (400, 0)
- TTS нода найдалі справа: (600, 0)
- Вертикальний відступ між паралельними нодами: 100-200px

## Правила

1. Кожен воркфлоу ПОВИНЕН мати рівно одну ноду "start"
2. Кожен воркфлоу ПОВИНЕН мати рівно одну ноду "system_formatter"
3. STT та TTS ноди мають бути включені, але з is_active: false,
   якщо голос не запитано спеціально
4. Custom ноди мають мати чіткий, сфокусований текст conversation_goal
5. Кожна custom нода повинна мати щонайменше інструмент search_documents
6. Використовуй intent маршрутизацію замість keyword для мультимовних агентів
7. Fallback edge гарантує що жодне повідомлення не залишиться без відповіді
8. Індекси нод мають бути послідовними починаючи з 0
9. Всі source_index та target_index в edges мають посилатися на дійсні індекси нод
10. conversation_goal має бути написаний мовою, якою працюватиме агент

## Вивід

Поверни ТІЛЬКИ JSON-об'єкт — без markdown, без пояснень, без
огорток коду. JSON має бути валідним і придатним для парсингу.

## Вхідні дані

Мій бізнес: [ОПИШІТЬ ВАШ БІЗНЕС]
Роль агента: [напр., консультант з продажів, агент підтримки, збирач лідів]
Мови: [напр., українська, англійська, мультимовний]
Голос увімкнено: [так/ні]
Ключові теми/відділи: [напр., товари, білінг, технічна підтримка]
Поля пам'яті для збору: [напр., ім'я, телефон, email, або нічого]
Спеціальні вимоги: [будь-які додаткові вимоги]
```
</Accordion>

<Tip>
  Після генерації JSON ви можете переглянути та змінити назви нод, conversation goals або інструменти перед імпортом. Формат шаблону воркфлоу буде доступний для прямого імпорту в наступному оновленні Revol.
</Tip>
